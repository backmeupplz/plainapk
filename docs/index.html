Plain APK

Apps straight from their releases, updated while you sleep.

Plain APK is a small Android app store that installs apps directly from the developer's GitHub, Forgejo or GitLab releases and keeps them up to date in the background, even when a project ships a new build every hour.

Download Plain APK

For Android 12 and newer, about 100 KB. Open the file on your phone and allow your browser to install it once; from then on Plain APK updates itself. The source is on Forgejo and mirrored to GitHub, and the release is signed with a certificate whose SHA-256 is 88:B4:92:AC:67:BB:10:2E:14:86:18:84:FA:0F:C6:83:ED:DA:0C:4E:FE:56:AC:C6:E4:D1:45:70:E0:73:27:E1.

How it works

You paste a repository link or pick an app from the catalogue, and Plain APK downloads the APK the developer attached to their latest release. Before installing anything it checks that the package name matches and that the app is signed by the same key as before, so a swapped file never reaches your phone.

It also looks at the apps you already have and offers to keep the ones it can match to a public repository up to date. On Android 12 and newer, updates for apps it installed happen silently in the background, including updates to Plain APK itself, and it works the same on GrapheneOS and other phones without Google services.

Nothing in the middle

There is no server, no account and no analytics. The catalogue is a list of apps in a public git repository that anyone can extend with a pull request, and your phone talks to the code forges directly, keeping everything it learns on the device.

For developers

If your releases already have an APK attached, your app works with Plain APK without any changes: people paste your repository link, or you add a line to catalogue.txt with a pull request to list it for everyone. Make sure every build has a higher versionCode than the last one and is signed with the same key, and you can release as often as you like. The publishing guide has the details and a release workflow to copy, written so a coding agent can follow it as-is.

When a release carries several APKs, Plain APK takes the one built for the phone's processor, then a universal one, prefers files named after your repository and skips debug and F-Droid builds. If it should take a specific file, put a pattern after your repository in the catalogue:

# catalogue.txt
https://github.com/you/app  app-*-release.apk
